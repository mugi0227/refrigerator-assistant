# fridge. — 冷蔵庫の相棒

スマホのカメラに見せて、検知音 → 期限読み取り → 5秒で自動登録。間違っているときだけ編集する、ローカルファーストの家庭用Webアプリです。

**v0.1 / 実機検証用プロトタイプ。iPhone SafariでのGemma速度・認識精度は未検証です。** ネイティブアプリのベンチマークをWebの実測値として扱っていません。

## 入っているもの

- ひとつのカメラ画面でJAN/GTINとGemma 4 E2Bの画像認識。登録・消費モード。
- パッケージ商品を保持して期限面を待つ状態管理。別フレーム2回の一致を確認してから5秒カウントダウン。新しい商品を検出すると前の候補を登録。
- 野菜・果物は印字期限を待たず候補表示。数量・状態スライダー・使い切り目安は編集可能。卵は見えている個数を扱い、箱の容量から推測しない指示。
- 検知音と保存完了音、編集、一時停止、キャンセル、直前操作の取り消し。同じ対象を映し続けたときの重複抑止。
- 手入力、数量の一部消費・使い切り、冷蔵/冷凍/常温の分類、期限順・検索。
- アプリ内の期限リマインダー、常備品の不足から買い足しリストを算出、買い物チェック。
- Gemmaによる在庫からの献立提案。期限切れとして記録された食材は提案対象から除外。
- IndexedDBへの端末内保存、JSONバックアップ/復元、PWAマニフェスト・アプリ本体のキャッシュ。
- 実物を認識せず、在庫にも保存しない「操作デモ」。AIを読み込む前に連続登録の流れを試せます。

## まず開く

公開URL: https://refrigerator-assistant.refrigerator-assistant.workers.dev/

Node.js 22以上。アプリ本体はビルド不要です。デプロイ用のWranglerは開発依存として固定しています。

```sh
npm ci
npm run dev
# http://localhost:4173
npm run build
# JS構文チェック + 52件のユニットテスト
```

`public/` がそのまま配信物です。`dist/` は生成しません。スマホからLAN上のHTTPアドレスを開く方法ではカメラ権限が使えない場合があるため、実機確認にはHTTPSで配信してください。

認証済みの環境では `npm run deploy` で再公開できます。`npm run deploy:check` は公開せず配信物を確認します。Wranglerの開発サーバー依存に含まれる `sharp` は脆弱性修正版の `^0.35.5` に上書きしています。

## Gemmaを使う

1. HTTPSのURLをスマホで開く。必要に応じてホーム画面に追加。
2. 設定 → 「モデルを保存して起動」。約2GBを端末に保存するため、Wi-Fi・空き容量を確保し、Safariを開いたまま待つ。ダウンロードは％・MB・経過秒で表示し、その後は実行環境の準備・AI起動を別の段階として表示する。
3. 準備完了後にスキャン → カメラを開始。中央の枠にひとつの商品を映す。
4. 牛乳などは商品検出後に期限面へ回す。野菜は種類・数量を確認すると登録待機に入る。
5. 間違っていれば5秒以内に「編集」または「キャンセル」。編集を開くと認識とカウントダウンを止める。

モデルURLから取得できない場合は、公式Web対応の `gemma-4-E2B-it-gpu.litertlm` を取得し、設定画面でローカルファイルを選択できます。汎用GGUFやAndroid専用の別形式ではありません。配布元の利用条件に従ってください。

モデルは固定したHugging FaceリビジョンからストリームでOPFSに書き込み、約2GBの追加ArrayBufferをJavaScriptに作りません。保存完了後は同じブラウザで再利用できます。AIの初期化はページを開くたびに必要です。「初回」は永続保証ではなく、Safariの容量整理・サイトデータ削除・モデル更新などで再取得が必要になります。途中で中断したダウンロードの再開には対応しておらず、不完全なファイルは再利用しません。

読み込み途中の段階を記録し、ページが再読み込みされた場合に前回の中断位置を表示します。白い画面になって戻る現象はSafariのメモリ不足などが疑われますが、この記録だけで原因は断定できません。保存機能は通信とダウンロード中の追加メモリを減らすもので、2Bモデルの起動・推論に必要なメモリを小さくするものではありません。

GemmaのJS実装に動画を丸ごと渡すのではなく、カメラから静止フレームを順次取り出して推論します。1回の推論完了後に次を実行し、遅れたフレームをキューにためません。画面の処理時間は実測です。最初から2〜5fpsで動くという前提にはしていません。SafariのWebGPUがあっても、モデル・ランタイム・端末の組み合わせで読み込み失敗や発熱・メモリ不足は起こり得ます。

## 誤登録を減らすルール

- JANは商品の識別子であり、通常は期限も商品名も含みません。名前はこの端末で学習した対応表、Gemma、または明示的に有効にしたOpen Food Factsで補います。DB未収録の商品はあります。
- GS1コードはGTIN・期限AI(15/17)等の限定的なサブセットに対応。未知AIは安全側に停止。スキャンしたURLはアクセスせず、ローカルで解析するだけです。
- 印字期限は「賞味期限/消費期限」の見出しと年月日が読める場合だけ。製造日、年月だけの表示、年のない表示は勝手に補完せず手入力へ。日付の読み違いを完全には防げません。
- 別の商品名が出たら前商品の期限を引き継がない。複数種類が同時に写ると自動登録を止める。1回にひとつの商品を見せる運用です。
- 同じ商品を複数購入した場合は、いったん枠から外してから次を映すか「同じ商品をもう1つ」を使う。パッケージの個体を映像だけで完全に区別する実装ではありません。
- 消費は在庫を負数にしない。単位・保存場所を合わせて期限の近い在庫から引く。卵などの個数は編集可能。
- 野菜のスライダーはユーザーの申告です。AIによる安全性・鮮度の断定はしません。初期日数は変更できる計画用の仮値で、食べられる期間を保証しません。

賞味・消費期限は表示された保存条件・未開封時の条件に関わります。開封後の印字期限をそのまま安全基準にせず、食品の表示や状態を確認してください。このアプリは食中毒や腐敗を判定しません。

## プライバシーと現在の範囲

画像・在庫をアップロードする自前API、Geminiへの自動フォールバック、アクセス解析はありません。在庫はこのブラウザのIndexedDBだけにあります。**夫婦の別端末との自動同期、D1、ログイン、バックグラウンドのプッシュ通知は未実装**です。期限通知はアプリを開いた画面内に表示します。

外部通信は、設定で開始したモデル/実行環境の取得（Hugging Face、jsDelivr）、バーコード実行環境の取得、任意で有効にした商品DB照会です。Open Food Factsは初期OFFで、有効時だけ商品コードを送り、画像は送りません。

Service Workerのキャッシュ対象はアプリ本体だけです。モデルは別途OPFSへ保存します。外部ランタイムの永続キャッシュや完全オフライン起動は保証しません。端末のデータ消去やブラウザの容量整理でモデル・在庫が消えることがあるため、設定から在庫をバックアップしてください。

## 構成

iPhoneでAltStoreを使って試すネイティブ版は [ios/README.md](ios/README.md) を参照してください。AIとカメラはSwiftで処理し、既存の食品管理画面を同梱します。ビルドはMac/Xcodeで行います。

```text
public/core.js           純粋関数・日付/GS1解析・在庫計算・スキャン状態機械
public/db.js             IndexedDBの原子的更新・履歴・取り消し
public/vision.js         Gemma 4 E2B / LiteRT-LM Webのローカル推論
public/model-cache.js    モデルのストリーム取得・OPFS保存・再利用
public/barcode-worker.js ZXing-WASM（BarcodeDetectorがない場合）
public/scanner.js        カメラ・音・逐次推論・停止/復帰・古い応答の破棄
public/app.js            スマホUI・在庫/買い物/献立/設定・操作デモ
public/sw.js             アプリ本体のキャッシュ
```

実行時依存は `@litert-lm/core@0.18.0` と `zxing-wasm@3.1.5` をCDNから読み込みます。LiteRT-LMはJSPI未対応のブラウザではAsyncify版を自動選択します（0.14.0で追加されたSafari向けの修正）。モデルは公式Web APIの対応リスト掲載モデルを使用します。今後のSDK更新では `vision.js` と `barcode-worker.js` のピン留めを再検証してください。

### 実機での受け入れチェック

牛乳を映す→検知音→期限面→登録音。トマトを映す→数量→登録。映したまま二重登録されない。編集・中断で勝手に確定しない。消費モードで卵2個→在庫が2減る→取り消しで戻る。再読み込み後も在庫が残る。画面を閉じるとカメラが停止する。10分連続使用で実測処理時間・発熱を確認する。
